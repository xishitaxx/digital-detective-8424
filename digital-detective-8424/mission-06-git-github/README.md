## 3. Commands / tools used

* **GitHub Pull Request interface:** Used to propose and review changes from update-about into main.

## 4. My understanding
Staging (`git add`) chooses specific changes for the next snapshot, while committing (`git commit`) permanently records that snapshot in local Git history. A branch isolates work from main so experiments or updates do not disrupt the primary branch, and a Pull Request lets collaborators review and discuss changes before merging.

### Task 6.1: Basic Git workflow
| Git operation | What it does in your own words |
| :--- | :--- |
| Check repository status | Shows which files are untracked, modified, or staged for the next commit |
| Stage selected changes | Moves specific file changes into the staging area so they will be included in the next commit |
| Create a commit | Saves a recorded snapshot of staged changes along with a descriptive message |
| View commit history | Lists past commits so you can see what changed and when |

### Task 6.4: Git command glossary
| Git operation | One-line explanation |
| :--- | :--- |
| Initialise a repository | Creates a new local Git repository in the current folder |
| Check status | Displays current modified, staged, and untracked files |
| Stage changes | Adds file changes to the staging area before committing |
| Commit changes | Records staged changes as a new commit in repository history |
| View history | Shows the sequence of previous commits |
| Create or list branches | Lists existing branches or creates a new branch pointer |
| Switch branches | Moves your working directory to another branch |
| Publish changes | Sends local commits or branches to the remote GitHub repository |
| Retrieve remote changes | Downloads and integrates updates from the remote repository |
